MEET THE AGENT / INSPECTOR PULSE

From project evidence to a traceable score.

A portfolio-only walkthrough of the automated workflow behind Pulse.

This tab is only part of the portfolio demo.

It is not a tab in the main project. The real Pulse agent works automatically: it tracks each completed project, starts reviewing the project evidence and applies the scoring instructions. The manual controls below are just a way to explore example scenarios.

The agent investigates. The portal makes it usable.

Inspector Pulse automatically reviews completed projects using their records, communications, delivery evidence and external feedback. It follows versioned scoring instructions and explains the result. Reviewed projects build a case history for understanding how Pollion works with each client, spotting recurring issues and improving the next delivery. The portal brings those findings into project reports, PM and client views, questions, reviews and exports.

Built by Ziad Ahmed for Pollion. This public version recreates the interface with invented records and scripted interactions; it does not access email, Plunet or client portals.

01

Identify the project

Start with an eligible order and verify its owner, scope and client commitments.

02

Read authorized evidence

Use case-linked emails, the relevant client portal and Plunet order facts. Training explains the workflow; it is not case evidence.

03

Reconstruct the timeline

Link actionable messages, replies, accepted deadlines, deliveries and external feedback to the responsible project phase.

04

Apply the instructions

Calculate communication, deadline, quality and order-record checks using the selected rule version. Explain deductions rather than inventing a score.

05

Preserve gaps and review

Missing required evidence creates a Technical Hold. Material contradictions go to Pending Review. Neither is a perfect score or a zero.

06

Present and revisit

Publish a traceable audit for review. Use dashboards and debates to investigate findings; human reviewers remain responsible for decisions.

Scoring version matters. This demonstration follows the V.02.00 Ziad test-workflow shape: communication 28, deadline 28, quality 39, Plunet checks 5. Client/resource communication split is 56/3 and 28/3 points. The original V.01.01 guide uses a separate 30/30/40 model. These are scoped versions, not interchangeable company-wide rules. Calculations keep precision; only display values are rounded.
